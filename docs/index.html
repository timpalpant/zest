C++23 × Zephyr RTOS

zest::

Small, expressive services for embedded C++—explicit errors, caller-owned storage, and Zephyr underneath.

Browse the API View on GitHub

Useful pieces, independently selected

ADC and GPIO

Typed devicetree handles with explicit setup, logical pin states, and expected results.

WifiManager

Association retries, DHCP readiness, connection status, and power-save control.

HttpClient

Session-style HTTP/1.1 and HTTPS with structured errors and bounded response storage.

BluetoothManager

BLE host lifecycle and central-role connections through an approachable stateful API.

BatteryMonitor

Oversampled battery-voltage readings plus an independent discharge-curve helper.

Sensors and actuators

Read-and-Decode/RTIO sensor access, filters, PWM outputs, buttons, and reusable LED patterns.

Network services

DNS, TCP/UDP, MQTT, SNTP, interface monitoring, provisioning, retries, and TLS credential ownership.

System building blocks

Fixed-capacity queues and threads, timers, work items, watchdog, RTC, identity, power, and retained values.

Feels like modern C++

#include <zest/wifi_manager.hpp>

zest::WifiManager wifi;
auto connection = wifi.connect({
    .ssid = "network",
    .password = "password",
});

if (connection) {
    printk("IPv4: %s\n", connection->address.data());
}

Embedded constraints stay visible

No hidden response heap

HTTP body storage comes from the caller, making capacity and lifetime explicit.

Errors are values

std::expected preserves errno and structured failure stages without exceptions.

Application-owned policy

Drivers, network pools, TLS trust, controllers, and devicetree remain in your Zephyr configuration.
